Продолжающийся сеанс Codex остается на Sol xhigh. Когда субагент действительно нужен, роутер выбирает для него Luna low или medium, Sol high, а для исключительной задачи — Sol ultra.

Этот репозиторий воспроизводит мою настройку выбора моделей для субагентов Codex через [JevRouter](https://github.com/BillionsBobby/JevRouter) или другой движок типизированных решений. Его можно дать будущему сеансу Codex как инструкцию: **прочитай этот файл, клонируй репозиторий, запусти установку и проверь результат**. Установщик меняет только локальные настройки Codex и сначала создает резервную копию. Серверное развертывание не требуется.

[Отдельный репозиторий бенчмарков](https://github.com/suenot/codex-jev-router-benchmarks) содержит [полный отчет](https://github.com/suenot/codex-jev-router-benchmarks/blob/main/BENCHMARK.md), запускатель, задания и трассы. Он охватывает 12 заранее заданных задач по исходникам Django, для которых Jev выбирал Luna low, Luna medium и Sol low, а также прежние выбранные задачи по поиску и исправлению кода. Цены рассчитаны по опубликованным тарифам API, а не взяты из списаний за подписку Codex.

**Новое сравнение четырех вариантов:** Шесть открытых задач с локальными файлами запускались по три раза на каждый вариант; все четыре варианта прошли строгую проверку в 18/18 случаях. Один агент Sol xhigh стоил по тарифам API **$0.337455**. Тот же агент по правилу необязательной делегации стоил **$0.346462 (на 2,7% дороже)** и не запустил ни одного субагента. Родитель Sol xhigh с фиксированным ребенком Sol high стоил **$0.786760**, а с ребенком, выбранным Jev, — **$0.572820 (на 27,2% дешевле фиксированного ребенка, но на 69,7% дороже одного агента)**. Новое правило убрало лишние субагентские сеансы в этой выборке, но **не доказало экономию относительно прямой работы Sol xhigh**. Это оценка по API тарифам, а не счет подписки и не проверка кеша продолжающегося диалога. [Независимый аудит и результаты по задачам](https://github.com/suenot/codex-jev-router-benchmarks/blob/main/benchmarks/mixed-2026-09-26/REPORT.md).

[Аудит экономики](AUDIT.ru.md) ([English](AUDIT.md)) разбирает расходы родителя и детей, другие роутеры и конкретный путь исправления.

**Стоимость полного процесса:** В 24 парных запусках 12 задач одна сессия Sol high стоила по тарифам API **$0.452677** (22/24 строгих проверок), а родитель Sol high с субагентом, выбранным Jev для каждой задачи, — **$0.657100** (21/24), **на 45,2% больше**. В шести групповых запусках тех же задач вариант с родителем и субагентами обошелся **на 182,5% дороже** одной продолжающейся сессии Sol high. Один парный запуск с исправлением Django дал обратный результат: оба варианта прошли локальный официальный тест, а родитель с субагентом стоил **на 60,7% дешевле**, но работал **на 50,5% дольше**. Учтены родитель, субагенты и Jev. Прежние показатели экономии 71,0% и 98,3% относились только к рабочей модели и Jev, **без учета родителя**. [Методика и ограничения](https://github.com/suenot/codex-jev-router-benchmarks/blob/main/BENCHMARK.md#full-codex-workflow-one-sol-high-agent-or-a-routed-subagent).

**Выбор до начала хода:** Одна корневая сессия Codex с моделью, выбранной заранее, обошлась по тарифам API в **$0.184377** с учетом Jev против **$0.452677** у ранее сохраненного Sol high (**на 59,3% меньше**). Строгая проверка дала **21/24 против 22/24**; запуски сделаны позже контроля и не доказывают равное качество или общую экономию. [Методика и трассы](https://github.com/suenot/codex-jev-router-benchmarks/blob/main/BENCHMARK.md#direct-routing-before-the-root-codex-turn).

## Что настраивается

| Настройка | Значение |
| --- | --- |
| Продолжающийся сеанс родителя | Сохраняет настроенные `gpt-6-sol`, `xhigh`; установщик их не меняет |
| Обычная задача субагента или резервный вариант | `gpt-6-sol`, `high` |
| Совсем простая ограниченная задача субагента | `gpt-6-luna`, `low`, только при высокой уверенности движка |
| Понятная ограниченная задача из нескольких шагов или небольшая правка с заданным подходом | `gpt-6-luna`, `medium`, когда движок предпочитает ее с достаточной уверенностью |
| Исключительно сложная задача или подтвержденная неудача Sol | `gpt-6-sol`, `ultra` |

Установщик задает только значения по умолчанию для субагентов, добавляет правила маршрутизации в `~/.codex/AGENTS.md` и убирает закрепленные модели из файлов ролей `explorer`, `reviewer` и `worker`. Если файлов ролей нет, он создает их. Родитель сначала решает, принесет ли пользу отдельный агент. Если да, перед `spawn_agent` он оценивает краткое описание задачи и явно передает выбранные `model` и `reasoning_effort`. Роль `reviewer` остается на Sol high, кроме исключительных задач для Sol ultra. Автоматический маршрут Sol low отключен: тариф за токен у него тот же, что у Sol high, а в прежнем замере эта категория обошлась дороже.

### Поиск и исследование

Роутер выбирает модель и для **делегированного** поиска в интернете, файлах или логах. Он выбирает модель для всего сеанса субагента, а не для каждого вызова веб-поиска или команды оболочки. Если родительский агент ищет сам, его модель не меняется. Один последовательный поиск, короткое чтение или проверку одного утверждения родитель выполняет сам. Делегирование оправдано параллельной работой, изоляцией большого контекста, независимой проверкой или прямым запросом пользователя. Для исследования в интернете подходит роль `default`, для чтения файлов и логов — `explorer`. Не надо вызывать Jev ради решения, нужен ли Jev.

| Задача субагента | Ожидаемый выбор |
| --- | --- |
| Найти одну функцию, точную запись лога или факт на известной официальной странице | Luna low при высокой уверенности движка |
| Собрать факты из нескольких заданных файлов или логов в таблицу | Luna medium при достаточной уверенности движка |
| Проверить одно утверждение по официальной странице или сравнить два описанных варианта | Родитель Sol xhigh сам; Sol high, если задача независимо делегирована |
| Сравнить актуальные источники, проверить противоречия или обобщить исследование | Sol high |
| Сопоставить логи нескольких сервисов или найти неоднозначную причину по файлам | Sol high |
| Исключительно сложное расследование или подтвержденная неудача Sol | Sol ultra |

Описание задачи для движка должно содержать цель и границы поиска без приватных логов, исходного кода и ключей. При неуверенности выбирается Sol high.

Это **маршрутизация по инструкции**, а не принудительный перехват инструмента. При проверке Codex CLI 0.156.1 вызов `collaboration.spawn_agent` не запускал хук `PreToolUse`, а текст задачи в вызове был зашифрован. Поэтому репозиторий не обещает автоматического контроля на уровне хука. [Документация Codex о субагентах](https://learn.chatgpt.com/docs/agent-configuration/subagents) описывает явную передачу модели и приоритет настроек ролей.

## Инструкция для Codex

Когда пользователь просит настроить Codex по этому репозиторию:

1. Прочитай этот файл и локальные инструкции `AGENTS.md`. Проверь, не указал ли пользователь другой выбор моделей.
2. Клонируй репозиторий в отдельную локальную папку. Не копируй в него ключи.
3. Выполни команды ниже, посмотри список файлов в пробном запуске и затем установи настройки. Перед изменениями установщик сохраняет резервную копию.
4. Выбери движок решений ниже. Запусти проверку. Сообщи, если не хватает настроек или соединение недоступно. Предупреди, что уже открытые сеансы Codex нужно перезапустить для загрузки новых настроек.
5. Не утверждай, что хук принудительно выбирает модель или что экономия гарантирована. Перед выводами о производительности изучи точность и расход токенов в отчете. Если текущая сборка Codex позволяет, проверь запуск настоящего субагента.

```sh
gh repo clone suenot/codex-jev-router
cd codex-jev-router
npm ci
npm run check
node scripts/install.mjs --dry-run
node scripts/install.mjs
npm run doctor -- --live
```

Зависимость JevRouter закреплена на конкретном коммите; npm может использовать GitHub SSH. Нужны Node.js 20+ и доступ к GitHub. Для нестандартного профиля Codex передай `--codex-home /absolute/path` в `install.mjs` и `doctor.mjs` либо задай `CODEX_HOME`.

## Движки решений

`CODEX_ROUTER_DECIDER` выбирает движок. Переменная должна быть доступна командам Codex. По умолчанию используется `jev`, поэтому существующая установка продолжит работать. **Меняется только движок решений; субагенты всегда получают модели Codex.** `http` и `command` обозначают способы подключения, а не аналоги Jev. Совместимый сервер должен принимать состояние в формате JSON и вопросы двух типов — `choice` и `noul`; одного совпадения адреса недостаточно.

| Значение | Подключение | Настройка |
| --- | --- | --- |
| `jev` (по умолчанию) | Облачный Jev через JevRouter | `TYPESAFE_API_KEY`, `JEV_API_KEY` или `OPENROUTER_API_KEY` |
| `laya` | Локальный сервер [Laya](https://github.com/NandhaKishorM/laya) | По умолчанию `http://127.0.0.1:8000/v1/systemone`; можно указать `CODEX_ROUTER_DECIDER_URL` |
| `kev` | Локальный сервер [Kev](https://github.com/jaredpalmer/kev) | По умолчанию `http://127.0.0.1:8009/v1/systemone`; можно указать `CODEX_ROUTER_DECIDER_URL` |
| `simple-jev`, `open-jev-zefan`, `open-jev-dasein` | Локальные серверы с ответом формата Jev | Встроенный адрес loopback; можно указать `CODEX_ROUTER_DECIDER_URL` |
| `nanojev`, `minojev`, `mini-jev` | Локальные серверы с преобразованием протокола | Встроенный адрес loopback; можно указать `CODEX_ROUTER_DECIDER_URL` |
| `semif`, `jevlike`, `anyjev`, `open-jev-nico` | Мост к локальной консольной программе или библиотеке | Установи исходный движок и задай переменную с моделью или контрольной точкой |
| `http` | Любой сервис с Jev-совместимым `POST /v1/systemone` | Обязателен `CODEX_ROUTER_DECIDER_URL` |
| `command` | Другой движок через локальную исполняемую обертку | Обязателен `CODEX_ROUTER_DECIDER_COMMAND`; аргументы `CODEX_ROUTER_DECIDER_ARGS` в виде JSON-массива строк |

[Справочник альтернативных движков](BACKENDS.ru.md) перечисляет все десять проектов, их реальные интерфейсы, переменные настройки и ограничения. Эти режимы необязательны; по умолчанию остается облачный Jev. Переменная `CODEX_ROUTER_DECIDER_TIMEOUT_MS` меняет время ожидания HTTP (15 секунд) или однократного запуска моста (120 секунд), от 1000 до 600000 мс. Вероятности локальной модели не становятся автоматически калиброванными под пороги этого роутера. Проверь выбор на собственных задачах, прежде чем полагаться на дешевые маршруты.

Для серверных движков `CODEX_ROUTER_DECIDER_API_KEY` добавляет bearer-токен, а `CODEX_ROUTER_DECIDER_MODEL` задает поле `model`, если оно поддерживается. Для `simple-jev` по умолчанию используется `Qwen/Qwen3.5-0.8B`; если сервер обслуживает другую модель, задай ее имя. Обертка `command` получает JSON-запрос через stdin и возвращает ответ формата Jev через stdout без запуска оболочки. В запросе есть `state` и `questions`; в ответе нужны `answers.tier` (`choice`, `confidence`, `probabilities`) и `answers.exceptional` (`noul`). Вопрос `tier` выбирает `luna_low`, `luna_medium` или `sol_high`; старый ответ `luna` по-прежнему выбирает Luna low, а прежний `sol_low` теперь дает Sol high. Ответ проверяют типизированные функции JevRouter. При ошибке или неверном формате выбирается Sol high.

Пример ответа обертки:

```json
{"answers":{"tier":{"type":"choice","choice":"luna_medium","confidence":0.9,"probabilities":{"luna_low":0.02,"luna_medium":0.93,"sol_high":0.05}},"exceptional":{"type":"noul","noul":0.02}}}
```

Для локальной Laya отдельно установи и запусти ее [Jev-совместимый HTTP-сервер](https://github.com/NandhaKishorM/laya#self-hosting-http-server-jev-compatible):

```sh
python3 -m venv .venv-laya
.venv-laya/bin/python -m pip install 'laya[serve]'
LAYA_HOST=127.0.0.1 LAYA_DEVICE=cpu .venv-laya/bin/laya-serve
```

Затем в окружении, из которого запускается Codex, задай `export CODEX_ROUTER_DECIDER=laya` и выполни `npm run doctor -- --live`. Чтобы описания задач оставались на машине, Laya должна слушать только loopback. При первом использовании могут загружаться веса моделей; дай серверу прогреться перед проверкой. У моделей Laya ограниченный размер входа, поэтому описания для маршрутизации должны быть короткими. Экспорт в `.zshrc` попадет только в процессы, унаследовавшие окружение этой оболочки; Codex, запущенному через графический интерфейс, может потребоваться отдельная настройка окружения.

Для Kev выполни [инструкцию по запуску локального сервера](https://github.com/jaredpalmer/kev/blob/main/README.md#quick-start) на порту 8009, затем задай `export CODEX_ROUTER_DECIDER=kev` в окружении Codex. По умолчанию Kev использует модель `kev-latest`; его сервер принимает нужные здесь текстовое состояние и типизированные вопросы. Если на сервере задан `KEV_API_KEY`, на клиенте укажи то же значение в `CODEX_ROUTER_DECIDER_API_KEY`. Веса и запуск модели остаются на стороне Kev.

[PlayJev](https://github.com/OmniJev/PlayJev/blob/main/playjev/serve.py) тоже предоставляет `/v1/systemone`, но требует кадры изображения и поддерживает только `choice`: текстовое состояние и вопрос `noul`, необходимые этому роутеру, он отвергает. Это модель для игр, поэтому для такой маршрутизации она не подходит.

Для несовместимого движка укажи локальную обертку, например `CODEX_ROUTER_DECIDER=command`, `CODEX_ROUTER_DECIDER_COMMAND=/absolute/path/to/adapter` и при необходимости `CODEX_ROUTER_DECIDER_ARGS='["--model","local"]'`. Обертка преобразует запрос и возвращает типизированный ответ. Если движок недоступен, вернул неправильный ответ или превысил время ожидания, выбирается Sol high.

## Ключ облачного Jev и приватность

Облачному Jev, выбранному по умолчанию, нужен `TYPESAFE_API_KEY`, `JEV_API_KEY` или `OPENROUTER_API_KEY` в **окружении команд Codex**. Передай ключ через свой менеджер секретов или окружение оболочки. Не записывай его в этот репозиторий, `AGENTS.md` или `config.toml`. Команда `npm run doctor` сообщает, настроен ли выбранный движок; `npm run doctor -- --live` проверяет настоящий ответ, не показывая ключ.

Маршрутизатор отправляет выбранному движку роль и до 4000 символов краткого описания задачи. С облачным Jev описание покидает машину; с Laya на loopback оно остается локальным. Распространенные признаки ключей и зашифрованное сообщение приводят к локальному выбору Sol. Эти проверки не находят каждый секрет, поэтому описание нужно очищать до передачи. Текст задачи не сохраняется; в `~/.codex/router-decisions.jsonl` записываются модель, роль, причина, время и укороченный хеш задачи. Если движок недоступен, выбирается Sol high. В проверенном режиме Codex `read-only` обращение к Jev было недоступно, поэтому также выбирался Sol. Установщик не ослабляет ограничения сети и песочницы.

## Прямой вызов и повтор после неудачи

```sh
printf '%s\n' 'Найди определение calculateTotal и сообщи путь к файлу.' \
  | node src/route.mjs --role=explorer
```

Команда возвращает JSON с `model`, `reasoning_effort` и `reason`. Первые два поля нужно передать в `spawn_agent`. Sol `ultra` выбирается сразу только для задачи, которую движок с достаточной уверенностью оценивает как исключительно сложную. После **существенной и проверенной неудачи Sol** начни новое описание для маршрутизации с `[codex-router:sol-failed]` и укажи, что именно не удалось. Родительский агент обязан проверить неудачу: сама метка не служит доказательством.

## Необязательная пакетная обработка решений

Если уже запланировано несколько независимых субагентов, можно оценить до восьми коротких описаний за один запрос:

```sh
node src/route-batch.mjs < examples/route-batch.json
```

Команда возвращает массив в исходном порядке. Для каждой задачи действуют те же пороги уверенности, что и при одиночном вызове. Неполный или неверный ответ переводит только соответствующую задачу на Sol high; сбой движка переводит туда весь ожидающий пакет. Для одной задачи используется прежний одиночный маршрут. Команда отправляет один запрос движку, если оценка нужна хотя бы двум задачам; некоторые локальные движки внутри могут обрабатывать вопросы по очереди.

Для **повторяющейся простой классификации** вне выбора моделей есть отдельная команда. Подготовь не менее трех коротких записей и один или два одинаковых для всех вопроса типа `choice` или `noul`:

```sh
node src/decide-batch.mjs < examples/decide-batch.json
```

Вход содержит 3–24 элемента `items` с уникальными `id` и `state`, общие `questions` и необязательный `review_threshold` (по умолчанию `0.8`). Результат содержит типизированные ответы и `needs_review` для каждой записи. Codex проверяет только отмеченные записи и выполняет саму работу: эта команда не исполняет задачи и не вызывает модель Codex. Неполные ответы и сбои движка требуют проверки. Не отправляй приватные записи облачному движку; используй очищенные данные или доверенный локальный движок. Распространенные признаки ключей блокируются, но проверка не гарантирует защиту всех секретов.

Пакетный вызов полезен, когда однотипные решения и входные данные уже готовы. Дополнительный вопрос к Jev о том, нужен ли Jev, сам требует вызова; поэтому здесь выбор основан на количестве и форме подготовленных задач. Экономия именно этих пакетных команд не измерена. [Отдельный бенчмарк](https://github.com/suenot/codex-jev-router-benchmarks/blob/main/BENCHMARK.md#four-tasks-in-one-parent-session) сравнил четыре маршрутизированных субагента с одной продолжающейся сессией Sol high: в этой выборке вариант с субагентами был дороже.

## Необязательный подбор навыка

[Мод Jev Skill Suggestion для Claude Code](https://www.aitmpl.com/component/mods/productivity/jev-skill-suggestion) использует хуки Claude. В этом репозитории есть отдельный хук Codex `UserPromptSubmit`: он ранжирует локальные навыки по описаниям, проверяет до трех кандидатов по содержимому `SKILL.md` и добавляет в ход не более одного подходящего навыка. [Codex уже загружает полные инструкции навыка по необходимости](https://learn.chatgpt.com/docs/build-skills), поэтому одно только предложение навыка не убирает начальный список названий и описаний.

Укажи каталог локальных навыков. Флаг `--hide-skills` отключает выбранные навыки в штатном каталоге Codex: тогда хук подставляет подходящий навык, а его запись исчезает из начального контекста. Без флага навыки не скрываются. Для этого режима используй доверенный локальный Laya, Kev или исполняемый адаптер:

```sh
export CODEX_ROUTER_DECIDER=laya
node scripts/install-skill-suggestion.mjs --skills-dir "$HOME/.codex/skills" --skills-dir "$HOME/.agents/skills" --hide-skills --dry-run
node scripts/install-skill-suggestion.mjs --skills-dir "$HOME/.codex/skills" --skills-dir "$HOME/.agents/skills" --hide-skills
```

Можно передать несколько `--skills-dir`. Без `--hide-skills` хук только предлагает навык и не экономит токены начального списка. Установщик делает резервные копии, сохраняет существующие хуки и записывает `~/.codex/skill-suggestion.json`. Перезапусти Codex и проверь новый хук через `/hooks`: пока он не признан доверенным, Codex его пропускает. После добавления нового навыка повтори установку. Штатный вызов отключенного навыка через `$skill` недоступен; напиши `$имя-навыка` в запросе, чтобы хук загрузил его напрямую. Навыки плагинов и системы не меняются.

По умолчанию хук не отправляет запросы облачному классификатору. Если ты сознательно разрешаешь это, задай `CODEX_ROUTER_SKILL_ALLOW_HOSTED=1` в окружении Codex и при установке с `--hide-skills`. Тогда выбранному движку могут уйти до 4000 символов запроса, описания навыков и до 700 символов текста каждого кандидата. При обнаружении распространенных признаков ключей или сбое движка хук показывает локальный краткий каталог; в таком ходе экономии токенов нет. Проверка не гарантирует обнаружения всех приватных данных. Экономия токенов и точность подбора навыков в Codex для этого режима пока не измерены.

## Откат

При установке создаются манифест и копии каждого измененного существующего файла в `~/.codex/backups/codex-jev-router/<timestamp>/`. Восстанавливай только файлы из манифеста. Если для файла указано `existed: false`, удаляй установленный файл лишь когда от него не зависят более поздние изменения. Правки, сделанные после установки, нужно объединить, а не перезаписать. После восстановления настроек перезапусти Codex.

У этой папки отдельный Git-репозиторий. Установка меняет локальные файлы Codex вне Git; установщик не коммитит и не публикует их.
