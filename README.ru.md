# Codex Jev Router

[English documentation](README.md)

Этот репозиторий воспроизводит мою настройку выбора моделей для субагентов Codex через [JevRouter](https://github.com/BillionsBobby/JevRouter). Его можно дать будущему сеансу Codex как инструкцию: **прочитай этот файл, клонируй репозиторий, запусти установку и проверь результат**. Установщик меняет только локальные настройки Codex и сначала создает резервную копию. Серверное развертывание не требуется.

## Что настраивается

| Настройка | Значение |
| --- | --- |
| Основная модель Codex | `gpt-6-sol`, уровень рассуждения `high` |
| Рассуждение в режиме планирования | `xhigh` (модель остается Sol) |
| Резервная модель субагентов | `gpt-6-sol`, `high` |
| Простая ограниченная задача субагента | `gpt-6-luna`, `medium`, только при высокой уверенности Jev |
| Исключительно сложная задача или подтвержденная неудача Sol | `gpt-6-astra`, `xhigh` |

Установщик добавляет правила маршрутизации в `~/.codex/AGENTS.md` и убирает закрепленные модели из файлов ролей `explorer`, `reviewer` и `worker`. Если файлов ролей нет, он создает их. Родительский агент оценивает краткое описание задачи перед `spawn_agent`, затем явно передает выбранные `model` и `reasoning_effort`. Ревью остается на Sol, если нет оснований для Astra.

Это **маршрутизация по инструкции**, а не принудительный перехват инструмента. При проверке Codex CLI 0.156.1 вызов `collaboration.spawn_agent` не запускал хук `PreToolUse`, а текст задачи в вызове был зашифрован. Поэтому репозиторий не обещает автоматического контроля на уровне хука. [Документация Codex о субагентах](https://learn.chatgpt.com/docs/agent-configuration/subagents) описывает явную передачу модели и приоритет настроек ролей.

## Инструкция для Codex

Когда пользователь просит настроить Codex по этому репозиторию:

1. Прочитай этот файл и локальные инструкции `AGENTS.md`. Проверь, не указал ли пользователь другой выбор моделей.
2. Клонируй репозиторий в отдельную локальную папку. Не копируй в него ключи.
3. Выполни команды ниже, посмотри список файлов в пробном запуске и затем установи настройки. Перед изменениями установщик сохраняет резервную копию.
4. Запусти проверку. Сообщи, если нет ключа Jev или сеть недоступна. Предупреди, что уже открытые сеансы Codex нужно перезапустить для загрузки новых настроек.
5. Не утверждай, что хук принудительно выбирает модель или что экономия уже измерена. Если текущая сборка Codex позволяет, проверь запуск настоящего субагента.

```sh
gh repo clone suenot/codex-jev-router
cd codex-jev-router
npm ci
npm run check
node scripts/install.mjs --dry-run
node scripts/install.mjs
npm run doctor -- --live
```

Зависимость JevRouter закреплена на конкретном коммите; npm может использовать GitHub SSH. Нужны Node.js 20+ и доступ к GitHub. Для нестандартного профиля Codex передай `--codex-home /absolute/path` в `install.mjs` и `doctor.mjs` либо задай `CODEX_HOME`.

## Ключ Jev

Команде маршрутизации нужен `TYPESAFE_API_KEY`, `JEV_API_KEY` или `OPENROUTER_API_KEY` в **окружении команд Codex**. Передай ключ через свой менеджер секретов или окружение оболочки. Не записывай его в этот репозиторий, `AGENTS.md` или `config.toml`. Команда `npm run doctor` сообщает только о наличии ключа; `npm run doctor -- --live` дополнительно проверяет настоящий ответ Jev, не показывая ключ.

Маршрутизатор отправляет провайдеру Jev роль и до 4000 символов очищенного краткого описания задачи. Распространенные признаки ключей и зашифрованное сообщение приводят к локальному выбору Sol. Эти проверки не находят каждый секрет. Текст задачи не сохраняется; в `~/.codex/router-decisions.jsonl` записываются модель, роль, причина, время и укороченный хеш задачи. Если Jev недоступен, выбирается Sol high. В проверенном режиме Codex `read-only` обращение к Jev было недоступно, поэтому также выбирался Sol. Установщик не ослабляет ограничения сети и песочницы.

## Прямой вызов и повтор после неудачи

```sh
printf '%s\n' 'Найди определение calculateTotal и сообщи путь к файлу.' \
  | node src/route.mjs --role=explorer
```

Команда возвращает JSON с `model`, `reasoning_effort` и `reason`. Первые два поля нужно передать в `spawn_agent`. Astra выбирается сразу только для задачи, которую Jev с достаточной уверенностью оценивает как исключительно сложную. После **существенной и проверенной неудачи Sol** начни новое описание для маршрутизации с `[codex-router:sol-failed]` и укажи, что именно не удалось. Родительский агент обязан проверить неудачу: сама метка не служит доказательством.

## Откат

При установке создаются манифест и копии каждого измененного существующего файла в `~/.codex/backups/codex-jev-router/<timestamp>/`. Восстанавливай только файлы из манифеста. Если для файла указано `existed: false`, удаляй установленный файл лишь когда от него не зависят более поздние изменения. Правки, сделанные после установки, нужно объединить, а не перезаписать. После восстановления настроек перезапусти Codex.

У этой папки отдельный Git-репозиторий. Установка меняет локальные файлы Codex вне Git; установщик не коммитит и не публикует их.
